# 工作区重命名与对话延续

Pi Mission Control 1.4.0 新增 `/project` 和可选 Podman sandbox 执行。默认由用户手动执行；AI 只能使用用户为当前会话、指定动作和目标创建的一次性授权。需要 Pi 1.3.0，已打开的会话先 `/reload`。

## 手动使用

查看当前工作目录、会话文件和授权：

```text
/project status
```

假设当前工作区为 `D:/projects/1`，把它改名为同级的 `2`，同时延续当前对话：

```text
/project rename 2
```

也可以指定完整目标路径；目标的父目录必须存在，目标本身必须不存在。不会覆盖已有目录。跨磁盘移动不支持，会报错并保留原目录。

切换到一个已经存在的目录，不移动原目录：

```text
/project switch "D:/projects/another project"
```

同一终端窗口会切换到保留历史的延续会话，后续文件工具、项目指令和资源使用新工作目录。原会话和额外备份保留，延续会话会有新的 ID。

关闭终端后，从新目录启动：

```powershell
Set-Location D:/projects/2
pi -r
```

新目录的会话列表中可以找到延续会话；`pi -c` 继续该目录最近的会话。使用自定义 `sessionDir` 时继续沿用对应的存储设置；若配置或启动命令显式写着旧目录内的绝对路径，下次启动前需将该路径改成新位置，本功能不会改写全局配置。

## 授权 AI 执行一次

```text
/project allow rename 2
```

或者：

```text
/project allow switch "D:/projects/another project"
```

命令会在对话中记录明确的动作、目标和一次性授权编号。随后告诉 AI 继续，AI 调用 `project_apply({authorizationId:"编号"})`。AI 也可通过 `project_status` 查询授权。

授权只在本会话内有效，十分钟后过期；使用后失效，不能换一个目标执行。重载、切换会话、会话树导航、全局停止也会清除授权。授权不会写入全局配置；恢复旧会话中的授权消息不能重新启用它。

撤销授权：

```text
/project revoke
```

AI 工具会结束当前回合，等工具结果和当前回合保存、Pi 完全空闲后再迁移。不要把 `project_apply` 与其他工具放在同一批调用里。若存在排队输入，操作会拒绝，先处理排队内容再重新授权。

这是一项工具级授权机制，不是限制不受限 AI 的操作系统权限。请通过本功能重命名工作区，不要用 shell 命令先改名后期待 `/reload` 自动修复路径。

## 会话、团队与自动任务

- 复制完整会话树，保留当前分支、压缩记录、原始消息、签名和会话名称；不会全局替换历史文本中的路径。
- 追加新工作目录说明，提醒模型正确理解旧消息中的绝对路径。
- 重命名前停止本会话的后台请求，并关闭持久成员的旧进程，释放目录句柄。
- `rename` 只迁移原项目目录内的成员 cwd、工作区 root 和额外只读目录。项目外路径保持不变，权限不会扩大。
- 持久成员的已保存会话会复制到新 cwd 对应的存储位置，再恢复成员。找不到已有成员历史时会拒绝迁移并回滚，避免静默丢失上下文。
- `switch` 到不同项目时保留成员原有的工作目录和授权。需要在新项目工作的成员，应另行明确授权。
- Goal 的目标、结果和预算计数保留，迁移后暂停；Supervisor 保持关闭。检查验证命令中的绝对路径后再 `/goal resume`、`/supervisor on ...`。
- 已停止的 shell 命令和模型请求不会自动接续，需要重新派发。其他 Pi 会话不受本操作控制。

## 备份、失败恢复和限制

备份和迁移日志保存在 Pi agent 目录的 `project-migrations/<操作编号>/`，默认位于 `~/.pi/agent/project-migrations/`：

- `original.jsonl`：主对话迁移前快照；包含私有对话内容，不要提交到 Git 或公开分享。
- `migration.json`：原目录、目标目录、延续会话路径和迁移状态，不包含对话正文。

目录重命名或准备失败会尝试回滚。若 Pi 的运行环境在切换期间创建失败，目标目录和延续会话保留，错误信息与日志会给出 `pi --session "完整路径"` 的恢复方式。不要手动删除备份后再排查。

以下情况会拒绝或需要先处理：

- `--no-session` 临时会话无法迁移。
- Pi 的 agent 配置目录必须位于工作区之外。
- **Pi Mission Control 的安装目录不能位于待重命名目录内。** 本地路径安装需要稳定的包路径；先把插件安装到例如 `C:/tools/pi-mission-control`，再重命名业务项目。本功能不修改全局 settings 或其他会话使用的插件安装路径。
- Windows 下，其他终端、编辑器、外部进程或 shell 仍可能占用目录。插件只负责停止本会话管理的任务；操作系统拒绝重命名时会保留备份并报告错误，不会结束其他进程。
- 通过显式绝对路径加载的其他扩展或外部服务可能仍引用旧目录，需要自行更新。项目内发现的资源由 Pi 在新工作目录重新加载，并继续使用 Pi 的项目信任检查。
- 迁移支持当前分支延续。历史分支内容原样保留；回到迁移前分支时，里面的旧工作区和成员定义仍是历史状态，应先检查再执行任务。

## 离线验证

```bash
npm run check
npm test
```

测试使用临时目录和确定性 provider，覆盖真实 Pi 运行环境切换、关闭后从新目录启动一个新 Pi 进程恢复记忆、真实成员进程重建、成员记忆保留、授权拒绝/撤销/过期、失败回滚、当前分支和自定义会话存储目录。不调用真实模型 API，不修改用户配置或实际项目目录。
