# 证据、变更影响与运行恢复

在已有验收结果需要复用、证据变化或执行中断时读取。对小改动保留必要命令、结果和版本即可，不建立与任务不相称的庞大存证体系。

## 证据与结论

先确定验收条件和需要观察的事实，再选择验证入口。行为改变关注实际分支及失败边界；结构整理关注结构和行为保持；低影响纯文案修改用文本、链接和必要格式检查。没有实现的功能不人为增加验证要求。

有意义时覆盖正常、违规和畸形输入及真实 CLI 退出行为。能导入、静态检查通过、函数存在或计数齐全，不代替实际功能证据。项目要求的检查仍须完成；诊断先归因和审核，不为清零改变行为、放宽标准或添加宽泛压制。

证据说明实际输入范围、命令、退出状态、源码或工作区身份和必要环境；记录未运行、失败和未知事项。区分执行完成、提交待审、正式接受、提交和推送，也区分检查器可用与被检查产品合格。

## 保留已接受证据

- 对已被接受引用的日志、报告和清单保存稳定快照；后续运行另存，不覆盖旧回执。
- 可变进度文件只作索引，指向稳定证据。读取旧结果时核其源码身份、所选视图、范围和当前仍适用的部分。
- 复用未受影响的结果，不在每次验收、周期汇报或恢复时重跑全套测试。
- 共享 helper 改变时列出受影响的调用者或条款，并做相称增量验证；不把历史全量报告当作当前源码的完整快照。
- 插件报告证据指纹变化时，先检查实际差异和用途。对确认受影响的目标重新绑定经过核实的证据；不通过恢复旧日志覆盖当前结果或篡改插件记录来消除拒绝。

## 中断与恢复

重载、超时或通知延迟后，先读取当前插件状态、已保存结果与必要的现场证据。通知迟到不等于命令未执行。不要仅因为没收到消息就重跑创建提交、推送、迁移、构建或其他可能产生效果的操作。

| 当前事实 | 处理 |
| --- | --- |
| 任务已成功结算，结果可读 | 收集旧结果并继续验收，不重派同一工作 |
| 任务仍在运行 | 保持负责人和所有权，继续独立工作或使用插件等待机制 |
| 任务失败且旧执行已确认停止 | 审阅错误及遗留成果，选择最小修复；需要新尝试时显式创建 |
| 进程状态未知 | 先核查留存制品和实际进程，按插件要求提供准确任务身份与停止证据，完成对账后再执行 |
| 用户暂停或要求等待 | 保留可编辑计划、成果和证据，不自动恢复 |
| 插件有工作区、权限、预算或决策约束 | 使用对应控制，按当前恢复指引处理；普通状态查询或重载不解除约束 |

不要把运行故障都交给用户作业务决定，也不要自行绕过约束。用户明确继续某项任务时恢复该项授权工作，不顺带恢复已取消任务或独立受限范围。

上下文压缩或重载后沿用原任务和已有证据，不从零规划、重建团队或重跑验证。保持用户选定的上下文模式；按宿主机制恢复必要信息，不把模式切换当作普通存笔记或故障处理手段。

## 提交与交付

保留已有的提交推送授权，满足具体条件后直接执行。提交前检查真实 diff 与暂存路径，只包含已授权交付，保护其他修改；按项目要求记录既有计划事件和验证事实。分支、主线集成、发行、构建及设备操作分别服从本次授权。

用实际 Git 结果区分本地提交、推送成功及远端 OID 核验。未执行的步骤明确说明，不能由命令计划或旧回执推断完成。
