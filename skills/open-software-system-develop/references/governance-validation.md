# 治理器与历史文档迁移专题

只在用户授权开发治理器、规范检查器或迁移历史文档时读取。本文件不向其他仓库引入 Open Software System 的规则。

## 根据实际角色检查

先读取本项目当前规范，确定每类对象的结构、命名、接口、证据和行为责任。新增目录或文件前，核对父子前缀、大小写、单复数、封闭目录名单、固定 basename、必要 README 及批准的新增文件范围。外部工具默认采用的目录结构不能直接视作本项目例外。

源码整理保留实际控制流、参数求值时机、输出字节、公开接口、架构独立性和资源所有权。例如某项目的 Build 七区及静态输入规则只适用于该项目指定的 Build 角色；Testing、治理器、产品和总控分别读取自己的要求。不能把一种分区或禁嵌套规则套给所有文件。

临时驱动、夹具、旧代码和证据放在项目允许的位置；项目指定受忽略的 `.agents/` 时遵守该位置，不把大量测试源码、压缩历史快照或固定输出塞进正式治理器。

## 按已授权标准选择处置

若用户允许严格、有界简化、通知分类，将对应覆盖与局限写入具体目标；仅改主目标说明不能替代叶目标标准更新。分类不取消原规范，也不扩大真实构建或产品修复权限。

| 处置 | 使用边界 | 交付要求 |
| --- | --- | --- |
| 严格检查 | 命名、路径、分区、字段、签名等明确可判定规则 | 可达实际判据、准确定位和相称正反例；违规准确报错 |
| 有界简化 | 动态语义难以穷尽，但存在可靠有限检查 | 说明支持的输入、检查范围和未知部分，不声称完整证明 |
| 通知 | 必要性、任意隐藏标识、人工意图等开放判断 | 具体条款提醒和人工判断边界，不冒机器通过 |

没有相应授权时，不能因为困难而降低验收要求。关键字、函数名、登记数量和统一返回值不证明条款已实现。区分检查器缺陷、输入错误、产品真实违规、缺失证据和通知；产品 FAIL 可以是检查器准确工作的结果，不能顺手改产品消警。

## 历史规范化

淘汰旧格式时按批准方案迁移，不以静默兼容掩盖错误。先保存原始字节和已有 Git/path/blob 等来源，再按任务、事件或记录建立旧新映射；身份声明和格式表示与历史事实分开处理。

保留历史 ID、时间、命令、退出状态、依赖、提交、授权及完成事实。原记录缺失身份或存在状态冲突时先核可用来源；不能补造分支、执行结果或真人批准。可无损重排的内容先做可审候选，需改变语义或接受边界的部分保留具体问题，交有权限者决定。

原始归档、格式迁移、新提交基线和之后的普通追加是不同步骤。候选本身或未来提交不能自证已建立真实基线；临时仓库只能证明验证算法，不证明真实仓库迁移完成。

验证治理器使用实际入口、适当夹具和已有有效证据，不自动启动 Full、发行、挂载或操作硬件。静态通过、代表用例通过与完整产品验收分别报告。
