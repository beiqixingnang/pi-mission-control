# 历史依据与插件随附维护

本文件供追溯偏好和维护 skill 时按需读取，不作为执行新任务的授权或事实。

## 来源与采用的原则

初稿由插件作者根据 Pi 对话“软件仓库开发-新”中 2026-10-22 至 2026-10-29 的用户要求及实际执行记录整理；后由该对话的执行者根据用户审阅意见修订。桌面审阅稿和后续仓库版本分开保存；历史备份不作为 skill 入口，也不随插件包分发。

历史中采用过 DeepSeek 执行加监督、Luna 执行加 Terra 监督，后改为四个 Terra 各负责一份治理文件。稳定保留的偏好是：按独立交付划分所有权、执行者负责实现验证自审、相关成员直接讨论、主模型维护标准并集中验收。具体模型、人数、额度策略和思考强度由当前任务指定。

早期按周期打断成员汇报，后来改为主模型直接读取保存的待验收成果。保留约定周期和低打扰核验原则，不把某次一小时配置设为所有任务的固定值。

某治理任务后来允许严格、有界简化和通知分类。该次授权不使未来任务自动允许降低标准。原先的 261 节、任务 ID、四个文件及统计只属于历史范围。

实际执行中出现过共享日志更新导致多个接受指纹失效，因而将稳定证据快照、增量另存及仅重开受影响范围纳入流程。也出现过套用外部 skill 默认小写目录而违反项目父子前缀和大小写要求的拟议路径，因而明确要求新增路径前核对项目规则。

## 与插件一起维护

此 skill 随 Mission Control 插件仓库维护，使用该仓库的目录命名和资源组织约定；不向插件仓库套用来源软件仓库的封闭文档树规则。

通过插件现有 Pi package 资源机制声明 skill，启动只提供名称、描述和入口，全文及本目录参考资料按需读取。把文件放进插件仓库不等于已安装或已加载，交付时区分文件修订、资源登记与实际加载验证。

插件负责提供能力、当前状态、权限约束和可核查结果；skill 负责协作方法与用户偏好。工具结构变化时同步有关角色及流程参考，不复制整套工具 schema、不写死版本号，也不把本正文重新注入每次请求。

维护时检查主文件的触发范围、相对引用和正常工作闭环；参考资料只在触发场景中加载。新的用户偏好应先区分长期原则和单次任务配置，再更新相应文字，保留已被替代要求的追溯来源，避免复活旧流程。
