# 暂停计划与自然语言目标控制（2026-10-28）

本轮基于 `a55d810` / 2.8.0，在隔离候选分支 `codex/paused-goal-planning` 实现 2.9.0。用户正在使用的开发 Pi 对话不参与测试、重载或控制。

## 行为

- 用户可以直接告诉 AI“暂停这个目标”“修改这个小节”“改好后继续”或“重启之前的目标”，由 AI 调用 `goal_pause`、`goal_edit` / `goal_update` / `goal_plan` 和 `goal_resume`。不要求用户输入斜杠命令。AI 也能主动暂停以调整计划，在自己的调整完成后恢复。
- 暂停与计划编辑分开。主目标、对应子目标和新增计划可以在暂停时编辑；只要求修改用户暂停的计划时，编辑后仍保持暂停。恢复不重置用量、预算或验收记录，也不解除独立迁移、权限、预算和未知进程阻塞。已经开始的成员任务沿用原有收束规则，相关定义变更仍需避免与未收束工作冲突。
- 截图中误用 `goal_stop` 的旧目标可按原 ID 恢复为暂停可编辑，必要时按用户的重启要求恢复。旧停止归档历史、子目标 ID 和任务记录保留，旧命令不自动重放。已经验收的目标不能借暂停工具隐式重新打开。
- 底部同时显示活跃与暂停主目标，统一使用“暂停中”标签。停止归档或验收完成的目标隐藏；超出行数时显示剩余目标数量。迁移待确认等独立运行状态单独显示，不借已归档目标的行展示。
- 状态与目标详情明确返回“暂停仍可编辑、不需要先恢复执行”。执行控制信息独立于目标定义，避免迁移暂停被误认为目标 ID、版本或验收状态发生改变。

类型检查、入口加载、Windows / WSL 回归与专用 TUI 的完整结果保存在同目录 `validation.json`、`tui-report.json`。四项容器集成检查按既有配置跳过；WSL 另跳过 Windows 专用 cwd 锁诊断，不将跳过计为通过。
