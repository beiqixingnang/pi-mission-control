# 上下文模式候选版实测（2026-10-20）

候选分支为 `codex/context-modes`，基于 `b6aaad0`。尚未安装到正式环境；用户的硬件开发 Pi 对话未被重载、停止或用于测试。

已实现两条路径：默认摘要模式采用较大的输入块、短中间摘要和独立的最终摘要预算；实验性笔记模式由当前工作模型维护 `index`、`handoff` 和主题笔记，在 Pi 原生安全边界换窗。模式、笔记和原始历史在同一会话 `/reload` 后保留。记忆只读取当前会话公开历史及本扩展自己的数据，不读取目标、任务或其他插件的内部账本。

目标提示同时要求执行前完整盘点并登记已知目标，工具容量不足时在同一规划阶段分批登记。执行中新增或调整范围先与用户讨论；滚动规划仅推荐用于经讨论的从零探索、最终形态或要求尚不明确的任务。状态、证据和阻塞更新仍可正常记录。

## 机制依据与预算

对照了本地保存的 `openai/codex` 历史源码，提交为 `e16b631d08cdf82773831f9bbfb793da687d5299`。`ext/history-notes/src/extension.rs` 将自动提示限制为 4000 字节；`tools.rs` 允许单份笔记存储至 1,000,000 UTF-8 字节，并提供字面子串历史查询；`core/src/compact_token_budget.rs` 的换窗路径跳过模型摘要。存储上限不等于每轮注入量，客户端源码也不能证明后端提示生成的质量。

本实现采用本地独立存储。入口上限为 1500 估算 tokens，交接上限 4000，主题笔记上限 8000，单次正文读取上限 2000。超长内容被拒绝并要求整理，不截掉末尾。只带入最新入口和交接版本，主题笔记按需读取；笔记保存回执不重复正文。缺失或过时交接、取消、写入失败时保留原上下文。

摘要默认输入预算为 64,000 **估算** tokens，中间正文上限 3000 字符；最终正文预算独立配置，仍受总输出预算限制。当前推理模型默认总输出为 16,384 tokens，实际最终正文上限为 8192 字符。旧配置中显式的 24,000 字符输入上限继续有效。密集代码可能超过启发式 token 估算，提供方 usage 与字符数均单独记录。

## 真实模型与容量

在 WSL 使用用户已配置的 `gptcodex/gpt-6-luna` 线路，发送可复现的合成源码审查历史，没有发送实际硬件源码。材料分为八批，包含不同模块、分支常量、相似目标 ID、后续纠正、未验收状态和精确续点。`o200k_base` 计数为 **986,833 tokens**，这仍是该自定义线路的本地估算，不冒充整窗实际 usage。

单请求探针中，提供方接受了 **904,144 输入 tokens**，其中 515,968 为缓存读取；也接受了 772,144 和 516,144。它拒绝了本地估算 950,000 和 986,833 tokens 的整窗请求，错误为上下文超限。配置中的 1,050,000 窗口未被验证。这里记录的是成功/失败探针，不据此推断精确窗口上限。

## 同一批材料的结果

耗时包括各模式内部调用和最后问答；不包括独立容量探针。14 项检查覆盖八个批次标识、纠正后的 ID、revision、下一文件与行号、未验收状态和生产会话限制。

| 模式 | 耗时 | 模型请求 | 记忆检查 |
|---|---:|---:|---:|
| 摘要，64k 估算输入预算 | 76.552 秒 | 15（13 块＋合并＋问答） | 14/14 |
| 摘要，128k 估算输入预算 | 51.700 秒 | 9（7 块＋合并＋问答） | 5/14 |

上表只统计摘要与问答阶段，不包括工作模型最初阅读材料的时间。

连续读取另做了相同八批材料、每两批换窗一次的完整流程比较。两组都包含工作模型阅读、记忆维护、四次换窗及最终问答/回查：

| 完整读取流程 | 耗时 | 模型请求 | 记忆检查 |
|---|---:|---:|---:|
| 摘要模式，64k 输入预算 | 189.007 秒 | 31（8 次读取＋20 次摘要＋3 次问答/回查） | 14/14 |
| 笔记模式 | 166.424 秒 | 28 | 14/14 |

笔记由 6luna 自己生成，脚本未预先提供答案笔记。最终入口为 962 字符、交接为 1361 字符；最后窗口的本地估算为 4355 tokens，摘要连续读取组为 2200。没有为凑预算增加笔记长度。这次笔记流程少用约 23 秒，但不能从单轮合成试验推断稳定提速。

性能基准直接调用同一摘要/记忆运行时。笔记保留最近交接工具边界，摘要保留最近工作回复；真实 Pi 还会按 `keepRecentTokens` 保留近期消息，生命周期另由 TUI 与 SDK 验证。因此数字不能直接等同真实项目 TUI 中的完整审查耗时。两组只检查指定事实和续点，没有自动验收全部代码语义。

| 模式 | 非缓存输入 tokens | 缓存读取 tokens | 输出 tokens |
|---|---:|---:|---:|
| 摘要 64k | 1,026,158 | 27,776 | 2727 |
| 摘要 128k | 1,015,386 | 11,904 | 1966 |
| 摘要连续读取 | 2,283,404 | 328,064 | 5526 |
| 笔记（含读取） | 901,333 | 3,734,656 | 7912 |

以上是线路返回的 usage。配置中的价格为零，不能据此声称实际免费或推算中转账单。不同运行的缓存情况与延迟可能变化，单轮结果不能推广为普遍更省。

最初摘要提示的结果为 64k 组 13/14、128k 组 4/14。64k 组曾恢复旧的错误 ID，因此增加了保留必要标识和“后续纠正覆盖旧值”的要求，再得到上表结果。较大分块即使更快仍明显漏信息，建议保持 64k 默认。单轮合成检查不能保证真实任务没有语义遗漏，也不证明所有模块已完成实际审计。

原始失败记录保存在结果文件中。最早笔记基准驱动没有像实际插件那样拒绝缺少交接的换窗请求，导致未换窗并最终超限；该驱动缺陷已修正，早期结果不用于比较两种模式。

## 回查、取消与升级

记录检查发现搜索可能命中它自己的查询参数。现已从派生历史索引中排除记忆工具调用/回执和维护提示，索引版本升级只重建本扩展的缓存，保留笔记及 Pi 原始历史。

另做真实 6luna 检索探针：只提供当前短笔记，要求找回早期 `src/stage_0/decoder_0.ts` 中未写入笔记的常量。模型搜索并读取原始 `source-batch-0`，准确返回 `initial_result=204`、`guard_mode=4`；3 次请求用时 9.237 秒。这一探针与主体 28 次请求分开计算。旧的自我命中记录保留供核查，不能算作有效证据；最终候选已重新跑完近百万材料的笔记试验。

Windows 和 WSL 均运行类型检查、扩展加载及完整回归：各 221 项，217 通过、4 项容器集成测试跳过，零失败。新增覆盖包括笔记版本、索引升级、Unicode 分页、分支隔离、过时交接、取消、reload 使旧换窗失效、未知上下文用量、工具尾消息保留及真实 Pi 自动续跑。

专用 WSL 会话仍为 `插件回归测试（WSL）`，ID `85289420-ef5b-472a-82ca-5387b6998102`。使用 `scripts/test-task-policies-tui.py` 从正式基线升级候选，完成 21 项检查：同一 Pi 进程中的字面 `/reload`、目标状态保留、笔记换窗、历史回查和切回摘要。用户的正式会话无需配合测试。
