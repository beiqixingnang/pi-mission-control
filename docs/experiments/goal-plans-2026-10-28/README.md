# 可选执行计划与成员编辑授权（2026-10-28）

基线 `b4553c4` / 2.10.0；候选 `codex/optional-goal-plans` / 2.11.0。本次同时修复未激活主目标无法直接归档的问题，机制分析见 `../goal-stop-2026-10-28/README.md`。在隔离检出开发与验证；不操作实际开发 Pi 会话。

## 使用

每个主目标和子目标可选择保存一份执行计划，不强制填写。创建 `goal_plan` 时可传 `plan`。主模型用 `goal_tree(goalId, section:plan)` 读取当前内容和 `planRevision`，再用 `goal_plan_update(goalId, plan, planRevision)` 添加或编辑；`plan:null` 移除计划。支持最多16000字符的文本／Markdown。目标详情面板显示计划与编辑授权。

例如主模型登记具体方法和常规决策：

```json
{
  "goalId": "child-id",
  "planRevision": 0,
  "plan": "1. 读取已有接口和测试夹具。\n2. 在已批准文件中实现批次。\n3. 复用有效证据，补充受影响测试。\n4. 汇总结果和未覆盖项；常规细节自行决定。"
}
```

派发给成员的任务包含本目标与上级计划的有限预览；成员通过 `goal_context(section:plan)` 分页读取完整文本和当前版本。可按目标 ID 阅读上级、下级或明确授权的同一主目标内计划。

主模型调用 `goal_plan_authorize(goalId, member, mode)`，`once` 允许一次实际成功修改，`permanent` 持续允许修改，`revoke` 撤销。授权精确绑定目标与成员 ID，不依赖可复用名称，不自动授予父子目标或其他成员。长期授权跨任务、重载及会话迁移保留。成员用同名 `goal_plan_update` 工具编辑，身份来自任务令牌；无法通过参数伪装另一成员或自行授权。

## 边界

计划有独立版本，旧版本写入被拒绝。非法、过时、未实际改变内容的写入不消耗一次性授权；成功写入、消耗授权和记录工具请求在同一 SQLite 事务中完成。相同任务请求的网络重放返回原结果，不再修改。任务结束、取消或执行世代变化后，旧令牌不能写入。

计划只描述现有批准范围内的方法。计划编辑不修改目标／验收版本、标准、任务范围、预算、暂停状态，不重启正在执行的工作，也不授予文件操作、下游派发或他人计划编辑权限。已关闭目标需先明确恢复或重开。更新与授权有审计事件；计划文本和授权按原目标保存。
