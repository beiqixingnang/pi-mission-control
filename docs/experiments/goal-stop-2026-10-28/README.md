# 未激活主目标直接归档（2026-10-28）

基线为 `b4553c4` / 2.10.0，随可选执行计划一起合入 `codex/optional-goal-plans` / 2.11.0。在隔离检出开发和验证，不操作实际开发 Pi 对话。

截图中的 `Goal identity changed` 源于 `goal_stop` 只读取当前选中的 mission，再将传入 ID 与它比较。目标账本已经支持多个主目标，但停止入口仍沿用单目标约束。旧目标无法直接归档；为了归档而激活又会受到当前工作和暂停状态的切换限制，因此需要修复。

`goal_stop(goalId)` 现在解析指定主目标，可直接停止归档未激活、计划中、暂停或阻塞的目标。省略 ID 保持停止当前主目标的行为。不激活旧目标，不解除其执行阻塞，只取消它自己的任务树和待处理交付。已有任务产物、子目标验收证据和未知进程记录保留；未知进程不会因为归档被宣称已停止。重复调用返回已有归档。未知 ID 和子目标 ID 给出明确错误；已验收主目标保留原验收和归档状态。

底层归档只在 ID 匹配时移除当前选择。计时、临时成员清理和暂停清理也按所属目标区分，不清除另一目标的用户暂停、迁移阻塞或待开始唤醒。等待旧任务异步取消期间新建或切换目标，最终收尾同样不会清空新目标。底部面板沿用已关闭主目标的过滤规则，归档成功后隐藏旧目标。

回归覆盖三类未选中主目标、无当前选择、旧账本缺少保存行、重复归档、非法身份、既有验收证据、当前任务继续执行、只取消旧任务树及交付、未知进程保留、异步收尾、新目标的暂停保留和底部面板更新。真实 Pi 离线工具测试与专用 WSL TUI 覆盖模型按 ID 归档、当前目标仍活跃、当前用户暂停不变，以及原进程字面 `/reload` 后的持久状态。确定性 provider 用于验证工具链，不评价真实模型对任意自然语言的理解质量。

完整测试结果与归一化源码哈希见 `../goal-plans-2026-10-28/validation.json`；专用会话检查清单见同目录 `tui-report.json`。
