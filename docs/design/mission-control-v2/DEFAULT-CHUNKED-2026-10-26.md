# 摘要默认分块与压缩故障恢复

插件 2.6.3，Pi 1.4.0。摘要模式默认使用现有分块通道，不再因为没有独立摘要模型配置而自动进入 Pi 原生整段摘要。没有独立配置时，以当前会话模型执行有界分块及合并；已有主/成员独立配置、共享默认值及环境配置仍优先。已明确配置但不可用的模型不回退，缺少模型的错误配置仍停止并给出原因。显式 off 保持其原含义：退出分块、使用 Pi 原生压缩。笔记模式及用户的模式选择规则不变。

compaction_model 状态报告提供 engine 和 modelSelection，区分当前模型默认分块、独立配置及显式原生模式。当前模型作为默认摘要模型是默认策略，不是配置线路失败后的回退。默认分块继续使用输入 token/字符预算、短中间摘要、旧检查点合并、成功块缓存、请求重试及有限降载；不发送完整长历史作为兜底。生产环境的现有独立配置不会被覆盖。

Pi 的 Context overflow recovery failed 前缀说明恢复步骤，并不证明摘要请求本身超限。错误分类会逐层剥离已知压缩/摘要包装，再判断内层原因。临时上游故障进入原小块的有限重试，必要时由持久冷却继续压缩；它不会触发无效的上下文拆分，也不直接重复原来的超长推理请求。真正的摘要输入超限继续拆分，余额/认证错误及明确用户取消继续停下。完整原始原因仍保存在诊断和恢复记录中。

reload 会给旧版丢失 nextAt 的临时压缩失败补回重试时间，保留故障 ID、累计请求、目标预算和原模式。已有重试时间不会因再次 reload 而推迟，用户暂停、Escape、迁移暂停及预算仍由原控制逻辑约束。新规则不重新派发已经执行的项目命令。

测试覆盖默认多块请求、重载保留、显式原生模式、独立模型不可用、成员路径、错误包装、旧记录恢复、取消及暂停。Windows 完整 340 项中 336 通过、4 个需显式容器环境的用例跳过；WSL 完整 340 项中 335 通过、另跳过 Windows 专属占用测试。两端 46 文件类型及两入口/55 工具加载通过。专用 WSL TUI 149 项检查通过，在原进程 literal /reload 前后注入截图中的错误，检查故障冷却后的自动压缩和续接，并保留工作区迁移往返回归。完整结果见同目录 receipt。

另对实际软件主对话日志做隔离的离线结构回放：约 42 MB 日志中，待压缩内容含 892 条历史消息、22 条回合前缀消息及约 10.2 万字符旧摘要，默认通道产生 13 次摘要/合并调用，最大请求约 14.2 万字符，低于 19.2 万字符预算。该回放用本地替身返回摘要，网络请求为零，验证分块路径和预算，不评估实际模型摘要的语义质量。没有操作、重载或暂停生产开发 Pi。
