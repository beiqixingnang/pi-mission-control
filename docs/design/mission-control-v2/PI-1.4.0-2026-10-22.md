# Pi 1.4.0 升级与插件兼容验证

检查日期：2026-10-22，Asia/Shanghai。插件基线为 2.5.1，commit `1e1fe30246e8ff033851767be5676ce7f0e585d5`。本轮先升级 Debian WSL 的 Pi 并验证，再升级 Windows；不使用用户硬件开发会话进行测试。

## 更新日志与影响

实际读取 npm 发布包的 `CHANGELOG.md`；Pi 1.4.0 发布日期为 2026-10-21。相关变化：

- 原生 compaction/branch summary 使用模型输出上限，`reserveTokens` 只决定何时触发压缩，不再限制摘要输出。插件自定义摘要继续保留独立输出预算、显式摘要模型、分块缓存和失败恢复；notes 模式继续使用原生安全工具边界。未移除插件现有保护或改写用户设置。
- 原生重试扩大对上游网关、stream disconnected 和部分 OAuth 暂时故障的识别，并避免把请求 ID 中的数字误当状态码。插件的补充重连和持久故障预算仍在；回归检查覆盖原生重试后交给插件、冷却恢复、人工取消以及不重复副作用。
- 修复恢复会话、树导航时部分扩展工具未激活的问题；插件既有宿主工具注册刷新继续保留，旧会话重载和 55 工具加载验证通过。
- 修复输出截断后孤立工具结果、空白工具输出、延迟工具装载时的部分提示缓存问题。
- 交互层修复并发扩展对话框、异常退出终端模式残留、中文标点邻接 Markdown 和 Windows shell 发现；不需要改插件 UI 或修改 Pi 二进制。
- Codemode 在 worker 忙时排队，与插件自身受管成员的并发和时限策略属于不同层，未替换插件派工逻辑。

对应上游发布记录为 `earendil-works/pi` 的 `v1.4.0`，安装包固定为 `@earendil-works/pi-coding-agent@1.4.0`，未追随浮动 latest。

## 安装与生效

WSL、Windows 的 npm 全局 Pi 均由 1.3.0 升级至 1.4.0；升级前的程序包备份和原始测试日志留在本地忽略目录 `.reference/pi-1.4.0/`。认证、模型设置和生产对话账本未作为升级对象。机器可读收据见同目录 `PI-1.4.0-2026-10-22.receipt.json`。

插件仍支持 `/reload`。Pi 宿主程序更新则需要在安全时点退出旧 Pi 进程，再 `pi -r` 恢复原对话；仅重载插件不能替换整个已运行宿主。本次没有关闭、恢复、重载或向生产硬件对话发消息。

测试 provider 是确定性离线夹具；未消耗真实模型额度，未测试实际网关新重试规则或摘要质量/速度，未运行容器用例，也未验证 macOS。本轮不声称修复了 SDK 的 `From chunk:` 终端日志或中转站的格式异常。
