# 跨电脑迁移完整 Pi 对话

插件 2.7.1；两台电脑安装同版本 Pi 和同版本插件，工作区仓库由用户分别克隆。迁移包只包含对话及其运行资料，不打包插件或工作区源码。模型服务账号与密钥由新电脑自行配置。

旧电脑在 Pi 空闲时输入 `/project export "C:/Pi-Transfers/software"`。包目录必须不存在，其父目录须存在。导出完成后复制整个目录到另一台电脑；可自行压缩传输，但导入前需要解压并保留内部目录结构。在已克隆工作区的终端运行 `pi --import-session "迁移包目录"`；已有 Pi 可 `/reload` 后执行 `/project import "迁移包目录"`。导入后按提示手动 `/mission resume`。

迁移内容包括完整原生 JSONL 历史、当前分支/压缩检查点与近期保留对话、原始消息 ID、目标树及版本、验收和任务回执、归档成员、所有成员日志、主/成员工作笔记及版本、历史搜索索引、输入预算与已学习限制、独立摘要模型路由、成功摘要缓存和本会话运行设置。验收引用的外部普通文件另行快照到迁移包的 evidence 目录，导入后映射到新运行时产物目录；不覆盖工作区里的源码或证据。原来已缺失的外部证据无法凭空恢复。

源 SQLite 通过 VACUUM INTO 读取包括 WAL 中已提交数据的一致副本。日志流式复制截止到捕获的完整 LF 边界；大记录不分行裁剪、不拼成一整个字符串，也不会读取尚未完整写入的尾部。运行中的成员在各自日志边界做快照；不同文件的快照不是跨文件的单个事务，因此推荐切换电脑前先让原任务停下并重新导出最终版本。

迁移包 transfer.json 登记格式、Pi/插件版本、源路径、每文件字节数、SHA-256 与权限。导入先核对版本和完整性，拒绝缺失、篡改、重复、目录穿越和符号链接。包有损坏时不会创建新运行时。版本不符会提示在新电脑安装相同版本后重试。该校验用于完整性，不是第三方发布者的签名。

导入创建新的主/成员 Pi 身份，保留目标、验收与任务 ID；根据明确源路径映射主/成员工作区、日志、产物、历史证据和插件路径，支持 Windows/POSIX 记录。原始历史正文不做全局字符串替换，旧路径可通过 project_resolve 查询。目标和提醒保持迁移暂停；旧运行/等待任务转为 interrupted，原先运行或未知进程仍是 unknown，不把远端进程当作已停止，也不重放旧命令。用户确认原电脑已停止并检查本机模型、外部依赖后，按原机制恢复或显式重试。

主会话与成员上下文均保留。已完成成员可继续使用映射后的历史；若旧成员停在没有干净工具结果的执行中，原有恢复规则保留其历史、为下一次执行使用新会话，避免把未完成工具调用当作已完成。未写入日志的生成内容、远端进程、外部未入库的任意源码/测试文件、模型密钥与未提交工作区修改不属于对话迁移。它们需通过各自途径搬迁，不能仅靠克隆仓库恢复。

导出及校验不调用模型。旧电脑对话和原始账本不被改写；导出读取的是静态快照，之后继续运行的新进展不会自动同步到这个包。导入也不是跨电脑实时协作。已有 HTML 阅读归档保持原用途，此迁移包用于实际恢复运行。

验证包含独立 agent home、真实 Pi 原生上下文投影和模式保留、成员日志/笔记、目标验收及证据映射、超 64 MiB 单条记录、不完整尾部、错误版本和损坏包。专用 WSL TUI 使用相同源测试对话和第二个独立目标 agent，验证 CLI 启动导入、同进程 `/reload`、导入阶段零模型请求及恢复后的实际工作区读取。完整回执另附。

2.7.1 补充：实际软件对话的大快照暴露了 Windows 文件清单按大小写归一、证据引用却按原大小写查询的问题；现已统一校验，并用大写 Proof.TXT 覆盖跨 agent 与 Windows→WSL 迁移。
