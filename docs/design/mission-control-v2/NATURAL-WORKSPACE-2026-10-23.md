# 自然语言工作区改名与切换

2026-10-23，2.5.3 → 2.5.4；Pi1.4.0。代码在隔离 checkout 开发，所有操作仅针对临时目录和专用 WSL 回归会话。

加载新插件后，直接对 Pi 说：

```text
把当前工作区改名为“软件仓库开发-新”
```

也可以说 `把当前会话的工作区切换到“D:\知识库开发\软件仓库”`。改名由插件移动当前目录并延续会话；切换指向另一现有目录。无需先输入 `/project allow`，无需在资源管理器里改名。中文、空格与标点名称放在引号内；含糊、条件式或讨论式表达由 AI 用自然语言澄清。

插件只从本次 interactive/rpc 输入中的完整、直接指令创建授权，绑定会话、动作、目标和十分钟期限。引用、历史、代码块、扩展生成的输入和助手文本不会重建授权。新的用户输入、取消、期限到达和 `/reload` 会使自然语言授权失效；`先别改名了` 可以撤销。旧 `/project` 命令路径保留。

主模型收到既有 project 工具的指导，读取 `project_status` 后单独调用 `project_apply`。执行工具只收取授权 ID，不能传另一个路径。暂停成员期间若收到新的指令，执行版本检查会取消旧操作；迁移准备期间取消则使用既有回滚机制。

Pi 的普通输入和工具上下文没有 `switchSession`。插件在原回合保存结束后，经公开 `sendUserMessage` 命令分发接口取得新的命令上下文。内部命令使用独立随机 nonce，只能消费内存中本次已排队操作；不是从旧授权文本重新解析路径。迁移仍走既有停止进程检查、路径校验、日志与原生会话替换流程，不修改 Pi 宿主。

排队工具回执不是完成证明，最终工作区通知和状态才确认迁移结果。目标、笔记、模型路由与证据沿用 2.5.3 的迁移机制，迁移后保持任务暂停，按用户授权再恢复。没有自动改任何用户生产目录，也没有操作或重载用户的开发会话。

验证覆盖：自然语言 rename/switch、准确目标、一次消费、来源隔离、自然撤销、新输入、过期、重载、真实 abort、成员停止期间取消，以及旧命令兼容。专用 TUI 沿用“插件回归测试（WSL）”，从安装基线原进程输入 `/reload` 加载候选，通过模型读取授权、执行中文/空格改名及改回，再分别 `/reload` 检查笔记、目标、摘要路由及相对工具。

完整结果见同目录 `NATURAL-WORKSPACE-2026-10-23.receipt.json`。测试提供方为确定性离线 fixture，不对真实模型的指令遵从率或超大历史迁移耗时作保证。
