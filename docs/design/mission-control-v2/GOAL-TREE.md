# 目标树与验收账本（2.1.0）

目标是持久的交付与验收单位；Task是一次执行或重试。Task completed不自动接受Goal，模型口头声称完成也不改账本。默认主目标、阶段、交付项三级；每个主目标可以包含并行叶子，一次只选中一个主目标。

## 持久化与升级

在原session的state.sqlite增加goal_nodes、goal_acceptances、goal_receipts、goal_missions四表及索引，不改session ID，不重建会话。旧meta.mission自动成为一级目标；已有完成证据以imported验收记录保留，不重新验证或杜撰子目标。meta.mission继续服务原运行核心；选中目标的运行快照与保存记录在同一事务写入。目标定义、验收与完成、重开及运行状态恢复同样使用事务。

ActivityClock按主目标保存，切换先结算旧区间，再恢复目标自己的用量；离线及未选中区间不补算。目标切换不重置budgetStartedAt、回合、token或用户控制。关闭、重载沿用已有成员中断和精确epoch恢复流程，不重放命令。

## 计划与执行

一级记录结果，二级组织阶段/验收批次；三级及更深的代码叶子目标应明确到具体文件或列明成员的文件/模块批次，以及工作、交付物和验收标准。目标粒度指导加入现有主模型工作规则和goal_plan/goal_edit说明，不另建插件或提示词系统，不强制每函数/文件各建一项。

可选scope保存在原节点JSON内：`{unitKind:"file"|"module"|"batch"|"artifact",items:string[],files?:string[]}`。提供时检查非空列表和大小上限，更新视为定义修订并使相关验收失效；没有scope的旧目标可继续使用，后续规划时细化。scope描述工作，不授予文件权限，也不能仅凭字段存在就断言粒度合理。不使用项目专属owner/profile枚举或固定文件数门槛。

成员任务自动附带目标ID/revision、父级阶段摘要、范围、验收预览、依赖满足情况、focus、nextStep和最近结果引用；超出预览的标准/范围通过只读goal_context分页完整读取。证据写入沿用授权工作区，不强迫创建新目录。没有有效checkpoint时不杜撰。任务完成不等于目标验收，有效证据复用，不要求逐行记录或循环自证。

goal_plan支持每批1–100项、批内key父子/依赖引用及原子校验。单会话最多5000个节点。深度由父节点推导，不能自报层级；依赖限同一主目标，连同父级验收依赖检查环。默认深度3，用户可通过`/mission goals depth 4`等授权至最多12级；不建议超过3级。授权保存在SQLite，不向模型提供自行提深度的操作。

dependsOn表示前置目标必须验收通过，祖先阶段的条件也约束后代叶子。显示顺序本身不是依赖。焦点用于主对话命令和默认派工；多个team_send可显式指定不同的可执行goalId。成员向下派工继承原目标，不自行扩大目标范围。Task保存goalId和goalRevision，旧版本任务结果不能直接作为新版本任务证据。

原生write/edit/bash/powershell经tool_call绑定焦点，结果保存为真实宿主工具收据。登记了子目标而没有可执行焦点时，写入和命令会返回具体指导；读取、状态和计划工具仍能使用。平面旧目标保持兼容。收据表示工具实际返回，不能独立证明某条命令覆盖了全部功能。

## 验收与返工

Goal状态包括planned、active、review、blocked、accepted、cancelled、skipped。状态更新不能直接写accepted；goal_accept要求精确revision、每项标准的证据、所有必需子目标已接受、前置条件满足且子树不存在运行或未知进程。主目标还沿用原来的未交付结果和执行清理检查。

一项目标对应一个当前验收记录，可含多条证据；旧记录不删除。证据来源：

| 来源 | 确定性检查 | 不能由此推断 |
| --- | --- | --- |
| artifact | 文件存在，记录大小、修改时间及小文件SHA-256 | 文件内容必然满足全部需求 |
| task | 同目标子树、精确目标版本、任务completed、进程stopped、结果文件存在 | 成员自行报告就是验收通过 |
| tool | 同目标同版本的宿主工具成功返回收据 | 测试覆盖率或命令语义正确 |
| acceptance | 当前有效的已验收后代记录 | 后代覆盖了父级额外集成标准 |
| statement | 有明确对应标准和说明，标为模型陈述 | 该说明是自动采集的测试结果 |

父级验收自动记录直接子目标验收ID，可直接引用已有效的下级结果，无需复制或重跑。重复接受同一已提交版本返回原记录，不发起额外模型审查。验收时检查已登记文件；元数据未变化不重复散列，大于16MiB文件只保存大小和mtime。没有对所有源码和隐式依赖建立自动变化检测。

定义修订或显式state:planned会使本目标和受影响父级、依赖分支的已验收结果失效，保留旧记录；无关兄弟目标保留。受影响依赖工作尚在执行时，先收束它再重开前置目标。重开已完成主目标不重置预算或用量。范围跳过/取消由用户命令给出原因，级联标记其后代并保存事件，不作为完成数。

## 界面与导出

主界面只在目标区域显示主目标与二/三级验收数。分母排除显式跳过和取消项，详情保留排除数量和原因，不把父子数相加当总完成率。`/mission goals`打开目标树，原`/mission`的目标页使用同一个组件、同一账本；可以查看原始验收标准、来源、工具/任务引用和历史。

goal_tree的树、证据、历史、任务和工具记录分页，长定义可用section:definition读取，避免截断JSON。剩余投入区间按未验收叶子的显式估算累加，并显示未估算项；不是考虑并发、阻塞和未知范围后的交付日期。

goal_export或`/mission goals export <new-file>`在SQLite事务内读取一致性快照，以exclusive-create写一次JSON，保存全部目标、运行快照、验收历史、当前记录、工具收据及产物引用。不自动定期生成JSON，也不复制外部产物内容。
