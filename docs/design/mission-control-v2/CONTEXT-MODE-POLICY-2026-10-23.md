# 上下文模式由用户决定

插件 2.6.2，Pi 1.4.0。主对话默认使用 summary；新建的受管理成员默认使用 notes。用户配置的成员默认值仍可覆盖，新默认值不会把有历史的旧会话从原模式切走。缺少旧设置时依据原有笔记检查点恢复，否则保留原生摘要行为。已选择模式继续保存在本扩展自己的每会话数据库中。

context_mode 不传 mode 是查询，单独调整输入预算不改变模式。工具实际执行不同模式前要求当前会话的一次用户授权。授权只来自直接的 interactive 输入或主对话的 RPC 用户输入；成员任务、其他模型输入、引用、代码和历史日志不能提供授权。识别常见中英文自然表达、主/子对话范围及对上一条具体模式建议的确认，不要求固定口令。有歧义时保持原模式。新的用户输入、会话切换及 reload 清除尚未使用的授权；已完成的模式选择不受影响。直接用户命令 /context mode summary|notes 继续可用。

两种模式的工作规则明确当前模式，要求模型不能为推进项目、保存笔记、重试或压缩失败而自行切换。summary 不例行维护 index/handoff，不执行 context_rollover；context_note 在 summary 中仍是可选的手动工作记录，不自动注入上下文。笔记的单条/批量写入及读取回执附带 mode 和 noteUse；列表保持原有数组格式。保存笔记本身不会改变模式或替代摘要压缩。

上下文扩展继续独立运行，不读取目标、团队或其他插件的内部账本。成员角色和初始设置通过宿主环境传入。授权规则限制模式切换，不限制查询、正常压缩或笔记模式中的换窗。
