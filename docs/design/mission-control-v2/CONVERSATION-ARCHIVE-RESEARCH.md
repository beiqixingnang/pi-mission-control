# 长任务联合对话归档：研究、页面原型与大输入验证

日期：2026-10-19。范围：研究与隔离原型；未修改、安装或重载生产插件，当前安装仍为 2.1.1。页面使用明确标注的合成数据，不是硬件仓实际验收报告。

## 结论

可行。建议以“一个可整体移动的归档目录 + 轻量 HTML 阅读器 + 分卷数据”为长任务的标准产物，而不是把全部内容塞进一个 HTML/Base64 字符串。可选的压缩包只是传输容器，解压后阅读；不能把“流式压缩 ZIP”误当成“已经解决单份会话的大字符串问题”。

目标、子目标、依赖、验收证据、成员身份、任务轮次及准确续点都能显示，但要从任务数据库和各会话日志联合导出。当前 `/mission export` 的 JSONL 与新阅读包应明确区分，不能只把现有 JSONL 的扩展名改成 `.html`。

## 当前实现中的实质性限制

| 入口 | 已核对的行为 | 新归档必须改变的点 |
| --- | --- | --- |
| Pi 1.3.0 原生 HTML | `exportSessionToHtml` 获取整个 entries，随后整体 JSON.stringify、Base64，再拼 HTML | 独立读取捕获的日志前缀，不调用这条整体序列化链路 |
| 插件 `exportPublic` | 联合主会话与成员历史，逐行输出，但只覆盖默认成员范围；不包含目标账本的完整结构 | 显式选择包含归档身份及任务，联合读取 SQL 与全部关联源 |
| `publicEntry` / `scrub` | 文本通常限 32,000 字符，工具参数字符串 16,000，数组 100 项 | 阅读预览可以短；实际正文不能靠这些限幅保存 |
| `lfLines` | 最大单条 LF 记录 64 MiB | 一条超长工具返回也可能超限，需要字段级令牌流或完整的大记录降级机制 |
| `transcriptPage` | 每条通常最多 1 MiB，单页扫描预算 4 MiB，允许标记 skipped | 可以继续用于 TUI 浏览，不能直接当完整导出读取器 |
| Store 看板 getter | `tasks()` 默认 LIMIT 1000；`goalReceipts()` 默认 20、最多 100；归档 getter 也有限额 | 使用专用只读游标/键集分页遍历完整表，不从看板 snapshot 拼完整归档 |
| GoalLedger.export | 单次 SQL 事务拿目标结构，但包含引用，不自动复制产物 | 可复用字段定义与验收语义，需分页取得全部历史、回执和来源信息 |

代码入口：`extensions/mission-control/index.ts` 的 `exportPublic`，`runtime/public.ts`，`runtime/jsonl.ts`，`runtime/transcript.ts`，`runtime/store.ts`，`runtime/goals.ts`。Pi 源码核对的是本机安装的 1.3.0，不声称代表其他版本。

## 页面布局与信息范围

使用浅色、固定左导航、中间主内容、右侧目标证据的结构。归档始终标注“导出时刻的只读快照”，不把运行中快照画成实时监控。

| 区域 | 展示的信息 | 可信度和关联规则 |
| --- | --- | --- |
| 总览 | 当前/历史主目标、二级/三级验收数、成员与来源数、主要阻塞、压缩/交接事件 | 完成数来自验收账本，不能用模型说完成或工具成功替代 |
| 目标树 | 递归层级、阶段依赖、状态、revision、负责人、下一步、范围排除及原因 | 支持用户已授权的更深树；导出端不生成或改写目标 |
| 验收详情 | 标准逐条对应证据、验收历史、重新打开原因、产物身份、工具与任务回执 | “模型声明”“产物引用”“工具回执”“下级验收”分开，文件哈希不等于行为正确 |
| 成员列表 | 每个 memberId 一个入口，当前与历史成员分组；内部按会话、任务与 attempt 过滤 | 不把每个任务窗口当一名新智能体；同名不同身份不能悄悄合并 |
| 对话 | 用户/助手公开文本、工具参数与返回、时间、模型、任务、压缩检查点、分支标记 | 工具配对键用 sessionId + toolCallId；缺结果应显示缺结果，不自动判失败 |
| 续点 | 最后 checkpoint、精确 next 文件/行/字节、已审/未审、阻塞、归属目标 | 只显示已记录的事实；没有登记的子目标或映射明确标缺失 |
| 完整性 | 所选范围、源文件/卷数、hash、损坏/缺失/未闭合尾行、脱敏/未嵌入项 | 不把带遗漏的结果显示成完整导出 |

关联使用已有的 `goalId / goalRevision / missionId / memberId / taskId / attemptOf / sessionFile` 和验收引用。旧任务没有叶目标绑定时显示“仅关联主目标/未绑定子目标”，不能按消息词语猜测。证据应能跳到相应对话位置；大产物默认显示引用、身份与可追溯读取记录，是否嵌入正文要单独选择。

当前原型已展示两个主目标、四个二级/十二个三级示例目标、验收种类、主/成员切换、轮次过滤、关联目标过滤、全文搜索和大正文分页。尚无完整分支选择器、真实验收历史展开、附件查看器或生产数据导出器。

## 数据路径与超长处理

```mermaid
flowchart LR
  A[主日志与全部关联成员日志] --> C[捕获完整记录前缀]
  B[SQLite 只读快照] --> D[目标与任务索引]
  C --> E[字段级流式解析]
  E --> F[完整正文分卷与元数据分页]
  D --> F
  F --> G[轻量阅读器]
  G --> H[最多40条消息或一段正文]
```

1. **导出时保持有界内存。** 顺序读取约 32–64 KiB 输入块；使用不聚合完整字符串的 SAX 令牌流，不能在后面再接会重建完整 entry 的 StreamValues/Assembler。普通 JSONL 逐行解析不足以处理一行上百 MiB 的正文。
2. **正文完整存储、预览有界。** 长工具结果与参数写成约 256 KiB 的 UTF-8 安全分段，记录原始逻辑文本字节数、段顺序和哈希。预览短不代表存储被截断。极长数组/对象同样要逐字段输出，不能沿用数组前 100 项的规则。
3. **索引落盘。** 用独立 SQLite 建消息 ID/parent、source、成员、任务、目标、时间、工具调用和正文位置索引，再按页写阅读包。主日志有其他分支时保留分支关系与导出选定 leaf；不能把压缩后的模型上下文当完整历史。
4. **浏览时保持有界。** 首次只装载小清单和必要目录，消息固定窗口分页或虚拟化；当前原型每页 40 条。全文按段查看，不能“展开”后追加整份 128 MiB 正文到 DOM。数据缓存采用小 LRU，浏览器自身的脚本/网络缓存需另作长期内存测试，不能只凭应用 Map 很小就宣布浏览器总内存恒定。
5. **检索完整正文。** 索引覆盖全部公开正文而非预览；跨分段关键词保留边界重叠，搜索结果跳回目标、成员和消息。扫描式原型能验证正确性；正式版应使用分区索引/后台检索，支持取消、进度和结果上限。

旧版 1 GB 日志中有大量重复 roster/goal 状态。可提取为独立状态事件、身份和任务变更以减少展示重复，但必须有旧版 schema 的专用适配、折叠计数和来源定位；不能把全部 custom 记录直接丢弃后声称信息完整。本次基准只验证扫描、文本选取和大字符串存储，不验证这套旧状态归一化。

## 活跃任务的快照、恢复和完整性

- SQLite 以只读连接和读取事务捕获一致状态，不创建 Store 运行实例，不争夺 owner.lock，也不暂停/重启正在工作的智能体。
- 每份日志捕获长度、身份和最后完整 LF 的边界，只读该前缀，不追着新追加的内容读。不同文件的边界分别记录；没有 flush 协调时，不宣称它们与 SQL 构成同一纳秒的全局原子快照。
- 发现截断、替换、缺失源或解析错误时，保留来源与未处理位置。中间损坏不静默跳过；允许生成明确标记不完整的阅读包，或者停止并从可靠边界续跑。
- 新目录独占创建，工作中用 `.partial` 与阶段清单；完成后再标 complete。取消、重试可以复用已验证分卷，但不能把上次捕获范围与新一次日志混成同一未声明快照。
- manifest 包含格式版本、导出选项、捕获时间/时区、源范围、成员/主目标集合、记录与正文统计、每卷 SHA-256、排除/缺失/脱敏清单。完整成功与部分成功必须不同。
- 已归档成员、退役 session、task.sessionFile 和旧版 roster lineage 都要纳入有界、可验证的来源发现。不能为方便而扫描打包整个用户会话目录，带入不相关对话。

## 离线打开方式与打包建议

首先做目录归档，完整复制目录即可搬运；之后再加流式压缩包分发。导出目录应包含轻量 `index.html`、小 manifest、元数据页、正文段和可选本地附件，外加格式说明与完整性数据。原始无损备份与经过公开字段筛选的阅读包是两个不同产物，不能混称。

不要依赖 `fetch(file://...)`、Service Worker 或 localhost 服务才能完成离线阅读。两种离线方案需要真正验证：

- **文件选择读取：** 入口嵌入小清单，用户选择归档目录/文件后，通过 File/Blob 分片读取 JSON 数据；主要优势是正文作为数据处理。目录选择 UI 和浏览器兼容性需实测，`showDirectoryPicker` 不能作为唯一入口，可研究普通文件/目录 input 降级。
- **静态脚本分卷：** 通过同目录 classic script 装载经过严格 JSON 编码的分卷，省去 fetch。当前原型采用此法验证分页交互；数据必须转义 `< > &` 与分隔字符，只通过 textContent/安全 Markdown 渲染。浏览器代码缓存、严格 CSP 与文件源行为仍需进一步验证，不能因 HTTP 预览成功就宣称 file 双击已成功。

本环境 Browser 工具明确拒绝 file 协议。没有尝试切换浏览器、关闭限制或通过其他自动化绕过。页面功能仅在仅含合成数据的 `127.0.0.1` 预览目录验证；**离线 file:// 双击兼容性尚未验收**。该限制不等于证明某个桌面浏览器不能打开本地 HTML。

## 本轮实测

原始数字和校验结果位于本机忽略目录 `.reference/artifacts/v2/export-research-2026-10-19/`。基准固定使用实验依赖 stream-json 1.9.1；它没有加入生产插件。真实旧日志只计数与哈希，未写出其聊天正文。

| 输入与处理 | 结果 | Windows 观察值 |
| --- | --- | --- |
| 真实历史文件 1,018,692,644 字节，完整流式扫描/令牌化/选定文本哈希 | 完成 4,684 根记录；不拼整份字符串 | 10.127 秒；峰值 RSS 114.9 MiB，采样峰值堆约 33.5 MiB |
| 单条工具消息的逻辑正文 134,254,534 字节，再加 128 MiB 自定义字段 | 正文完整写盘；SHA-256 与生成时一致；没有截断 | 36.684 秒；进程峰值 RSS 129.8 MiB，采样峰值堆约 33.5 MiB |
| WSL：同一真实 1 GB 输入 | 根记录数、源哈希、选定正文哈希均与 Windows 一致 | 19.133 秒；峰值 RSS 约 84.9 MiB |
| WSL：同一超长消息输入，仅哈希、不写正文 | 正文字节数和哈希与生成值及 Windows 写盘值一致 | 7.077 秒；峰值 RSS 约 90.9 MiB；不能与 Windows 写盘耗时直接比较 |
| 合成输入末尾追加未闭合记录 | 两条完整记录通过，最后 69 字节单独标为未闭合尾部 | 未把半条记录当有效对话 |
| 浏览器 12,000 条合成消息 | 成员第 4 轮可跳转；最后一页末尾标记存在 | 同时渲染 40 条消息，观察到全页 488 个 DOM 节点 |
| 浏览器直接定位 128 MiB 正文末尾 | 第 513 / 513 段命中末尾校验标记；当前段 30,840 字符 | 当时应用缓存 4 卷，清单估算约 456 KiB；这不是浏览器总 RSS |
| 全文搜索正文末尾独有标记 | 扫描 12,000 条消息，返回唯一长正文消息；可命中预览中不存在的内容 | 结束时应用缓存仍为 4 卷 |
| 归档分卷逻辑正文复核 | 逐卷反解 513 个正文分段，累计 134,254,534 字节，SHA-256 与原始合成正文一致 | 验证 JSON/HTML 特殊字符转义没有截掉尾部或破坏 Unicode |
| 缺失分卷与取消检索 | 暂时移走合成 GPU 最后一卷后，页面明确显示文件名与缺卷错误；恢复后可重新阅读。长全文检索可切回总览 | 没有将缺卷误显示为“没有历史”；仅操作演示文件 |

以上是本机具体输入的研究测量，不是任意 1 GB 档案的耗时承诺；两个 Windows 扫描实验曾并行运行。采样峰值堆与进程 RSS 是不同量，Node 的 128 MiB 堆上限也不是进程总内存上限。WSL 的同输入校验结果另存在 `*-wsl.json`，以产物记录为准。

页面关键检查还包括多个主目标切换、叶目标详情、从目标进入关联成员对话、长正文分页、恶意 HTML 样例以文本显示而不产生图像元素。没有把这些有限检查称为完整的 XSS 审计或正式性能验收。

## 正式实现顺序与验收门槛

1. **数据与完整性先行：** 建只读导出 snapshot/manifest、全量分页来源发现与 SQL 游标、旧版 lineage、字段流式提取、分卷与独立索引。定义保留/过滤规则并实现可核对计数。
2. **阅读器接入真实导出：** 总览、目标树、证据详情、成员内轮次、消息工具配对、时间/目标/分支跳转、长正文分段与全文索引。统一采用导出快照状态。
3. **边界与恢复验收：** 真实 1 GB 多源联合导出并核对所有公开正文与工具字段；单条 >64 MiB、多字节边界、巨型数组/对象、损坏中间行、缺失日志、取消/续跑、重复重试、活跃追加、任务/回执超过现有 getter 上限、Windows/WSL 路径与归档成员。
4. **离线与长期阅读：** 普通桌面 Edge/Chrome 的 file 双击/目录选择实际验证；不联网可读；长时间反复翻页、搜索、展开的浏览器实际内存测量；附件、Markdown、嵌入式私有转储和 HTML/URL 编码审查。
5. **最后才接插件：** 在显式的新格式参数/命令下提供后台导出、进度与取消；保留现有 JSONL；原会话 `/reload` 加载新功能。验证导出期间任务与预算不变、导出不会创建第二个运行 owner，再安装。
