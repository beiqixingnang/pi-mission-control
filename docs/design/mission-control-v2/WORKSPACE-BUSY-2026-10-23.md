# Windows 工作区改名占用与失败回执

日期：2026-10-23；2.5.5 → 2.5.6。

截图中的 `project_apply` 已接受准确的一次性授权，`queued:true` 表示迁移将在当前回合保存后执行。实际执行 `rename` 时 Windows 返回 EBUSY，准备流程已回滚；这次没有创建成功的延续会话，也没有把新路径登记为已完成迁移。

只读检查确认：启动 Pi 的父 PowerShell 也把源目录作为进程当前目录。现有代码在改名前已经让 Pi 自身 `chdir` 到源目录之外，但不能改变父进程的目录或解除其他应用的目录句柄。此前的 Windows SDK 测试只覆盖了 Pi 自身的 cwd，没有覆盖这个交互式父 Shell 场景。现在增加真实 Windows 进程占用用例，避免把普通成功改名测试当成占用场景已验证。

本次修改：

- 准备失败保留原错误码和失败原因到回滚 journal；在既有会话账本保存 `projectRelocationFailure`，并追加模型可读的失败回执。`project_status.lastFailure` 在 reload 后仍可读取，不把排队结果当成迁移成功；下一次迁移尝试清除旧失败记录。
- `project_status({diagnose:true})` 可选执行有超时、输出上限的 Windows 只读检查，只读取候选进程当前目录，列出与当前工作区相同或位于其内部的目录及 PID。区分父 Shell，排除查询进程和 Pi 自身；不读取环境变量或命令行，不结束进程或修改其内存/目录。
- 该诊断对 Windows 64 位进程尽力而为：不可访问、架构不支持或字段不可读时跳过，失败时明确返回 unavailable。它不枚举全部文件句柄，不把空结果当成“没有占用”的证明；非 Windows 返回不支持该诊断，迁移流程保持可用。
- 支持完整的直接表达，例如 `把当前本地工作区改名为“新名称”，并保留当前对话`，仍拒绝引用、条件式讨论、额外未授权动作及取消指令。

父 Shell 占用时需要用户释放那个进程持有的当前目录。可先安全退出 Pi，在原 PowerShell 把 `Set-Location` 和 `[Environment]::CurrentDirectory` 都设到源目录之外，再执行 `pi --session "原会话文件的完整路径"` 恢复原对话，然后重新提出准确的改名请求。使用完整文件路径很重要：Pi1.4 从其他项目按 ID 查询会提示 fork；这里应保留原会话，而不是 fork 到父目录。下一次 Pi 可以从中性目录打开原会话，减少父 Shell 锁住项目目录的情况。

`/reload` 可以加载本次插件修改，但不能释放父 Shell 或其他应用的 Windows 占用。没有关闭、重载或移动用户的实际开发会话/项目；真实项目检查只有目录、迁移 journal 和进程当前目录等只读元数据。

隔离 Windows 测试先在 2.5.5 代码上复现 EBUSY 和缺少失败状态，再验证补丁：原 session ID/路径保留、笔记不丢、回滚 journal 保留错误、查询返回准确测试 PID、外部进程没有被诊断工具终止、重建运行时后失败记录仍在；显式结束测试进程后，在原会话重试成功并保留笔记。WSL 的该 Windows 特定用例显式跳过；专用 TUI 则在同一 Pi 进程通过 literal `/reload` 加载候选，执行包含“当前本地”和“保留当前对话”的自然语言改名往返并检查已有数据。完整结果见同目录 receipt。
