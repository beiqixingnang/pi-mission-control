# 2.5.2：历史搜索占位参数与排除回执

日期：2026-10-22。基线为插件 2.5.1，commit `fcdea9fb6c0d23eb1620f38021baff4104e68acd`，宿主 Pi 1.4.0。运行中的用户项目对话没有被重载、停止或用于故障注入。

## 原因与改动

历史搜索的 `cursor` 是可选的续查凭据。模型在首次搜索时把空字符串补进可选参数，2.5.1 仅将 `undefined` 视为首次搜索，于是拒绝该占位参数。重复相同调用不会恢复。2.5.2 将省略、`null`、空字符串及纯空白都解释为首次搜索；非空字符串仍须通过现有签名、query、role、会话和分支校验，不接受伪造的 `0`。

另一类报错来自模型拿原始日志中的 `context_history` 错误回执 ID，再交给 `context_history read`。该 ID 可以存在于当前分支，但记忆工具自己的回执和提示刻意不进入公开搜索索引，以避免回显和递归查询。以前只有通用的 Unknown history 提示，容易误解成记录丢失。

现在已知但未纳入公开索引的分支记录返回 `HISTORY_ITEM_EXCLUDED`，说明改查原始 user/assistant 文本、使用搜索返回的消息 ID，并不要重复读取同一被排除 ID。不存在或属于其它分支的 ID 仍返回 Unknown history；不会为了消除错误而读取另一分支或把记忆工具回执重新加入索引。

实现只使用既有 `branch` 与 `history` 查询，无 schema 迁移、索引重建、新数据库或生产日志改写。已有 notes、revision、签名密钥和续查凭据保持可用。工具说明和 nullable cursor schema 通过原会话 `/reload` 刷新。

## 验证范围

先新增两个边界测试，在 2.5.1 上复现失败并保留日志，然后实现修复。

- `context-memory.test.mjs`：省略/空白/null 游标与首次搜索相同；批量请求兼容；真实 nextCursor 可跨重开数据库继续；伪造、篡改、跨查询/角色/分支凭据仍拒绝。原始消息能读取、记忆回执和提示不能检索、已知排除/不存在/其它分支 ID 区分正确。
- `context-pi.test.mjs`：用真实 Pi 离线 provider 提交包含顶层和嵌套占位参数的工具调用；验证错误回执提示后能读到原始消息，batch/null 在原会话 reload 后有效。只预期伪造游标及明确测试的排除读取失败。
- 专用 WSL TUI：在已有“插件回归测试（WSL）”中从 2.5.1 通过字面 `/reload` 加载 2.5.2；实际模型调用兼容空值、拒绝 `0`、解释被排除回执、读取原始消息、再次 reload 后执行 null batch。原 60 项长 RPC、压缩、故障恢复、目标与计时检查一并保留。
- Windows、WSL Node24 / Pi1.4.0 全套回归、严格类型与入口加载检查；完整结果在同目录机器可读 receipt。四项容器测试按配置跳过，未调用真实模型或中转站。

最终结果：Windows 和 WSL 全套各 290 项，286 通过、0 失败、4 项容器测试跳过；各 38 个源文件类型检查及两入口/55 工具加载通过。专用 WSL TUI 69 项检查通过。额外用隔离保留的 Pi1.3.0 程序包执行 31 项历史/notes 相关回归，全部通过，未回退全局宿主。各命令 exit 0；详见 `HISTORY-PLACEHOLDERS-2026-10-22.receipt.json`。

此前“首次模型响应等待较久”的上游暂时不可用错误与此次历史工具参数缺陷不同；本修复不改变提供方重连、压缩策略或项目执行权限。

## 安装生效

验证通过后更新本地安装目录。用户选择时机在当前 Pi 对话执行 `/reload`，无需为本次插件更新新建或重启会话。安装过程不向任何生产对话发送命令。
